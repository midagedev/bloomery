# Rust code quality strategy — the standard for review and refactoring

This document is the rule table that reviewers and refactoring rounds cite. Each rule has a number (`R1`…). A review report is written as `path:line — R-number — one line — size`. The sources are the official Rust guidance (API Guidelines, Rustonomicon, Unsafe Code Guidelines, clippy lint levels) and the incidents that actually happened in this repo. `AGENTS.md` Conventions holds the domain contract (correctness, measurement, comments). This document holds the **shape of the code**. If the two conflict, AGENTS.md wins.

## 1. unsafe — smallest scope, invariants in types

- **R1** One operation per `unsafe` block. Directly above it, one or two lines of `// SAFETY:` for **that operation's** invariant (which index is in range, and why). An `unsafe {}` that wraps a whole function is forbidden. (The 123 `undocumented_unsafe_blocks` hits were this violation.)
- **R2** If the same invariant repeats in three or more places, make it a **type** — a view with proven bounds (a shape like `StaticTileMut32` and `InBounds32` in cuda-device `view.rs`), or one safe wrapper function. Writing an invariant in a comment ten times gives ten chances to get it wrong.
- **R3** An `unsafe fn` must have a `# Safety` section in its doc comment (`missing_safety_doc = deny`, already a contract). Write only what the caller must uphold.
- **R4** Raw pointer arithmetic belongs only inside kernels. If host orchestration (`model.rs`, `lib.rs`) touches `*const`/`*mut`, that is the wrong layer — move it down into a method of the buffer type.

## 2. Types carry the contract

- **R5** **Numbers with different units have different types.** Element count and byte count, rows and keys and dimensions, words and f16 pairs — if one `usize` names them all, an 8x over-reservation compiles (ik #2501: `alloc` takes an element count and was passed a byte count). When such a value crosses a function boundary in host code, use a newtype (`Elems(usize)`, `Bytes(usize)`, `Rows`, `Keys`), or at least put the unit in the name (`n_elems`, `bytes`). `as` casts inside a kernel body are allowed (register arithmetic). Narrowing `as` in host code (`u64 as u32`, `usize as i32`) goes through `try_from`; if the failure is impossible, write the reason in `expect("...")`.
- **R6** Shape constants are `const` and const generics. Relations are fixed at compile time with `const { assert!(...) }` (`KEY_TILE == 32`, smem stride `≡ 16 (mod 128)`, `MMA_KEYS == MMA_WARPS * MMA_NTILE`). A runtime `assert!` is only for values known only at runtime (the cache length).
- **R7** A function whose result must not be dropped gets `#[must_use]` (launch builders, band computation, `segments_for`). A method that changes state takes `&mut self`. Interior mutability (`Cell`/`RefCell`/`OnceLock`) is only for levers (reading an env var once) and caches, with the reason in one line.
- **R8** A function with more than 8 arguments takes a parameter struct (12 `too_many_arguments` hits). A kernel launcher takes one `LaunchArgs`-style struct plus a stream. Field names carry the unit (R5).

## 3. Errors — enums for libraries, anything for binaries

- **R9** The public functions of the library crates (`gguf`, `model`, `gpu`, `qdot`, `threads`) return that crate's error enum (`LoadError`, `ModelError`, `GpuError`…). `Box<dyn Error>` and `String` errors are only for binaries (`gpu-gates/src/bin/*`, `q3k-*`).
- **R10** `unwrap()` and `expect()` appear only in gates, tests and `main`. Library crates have 0. The one exception is a place "where the type cannot prove the failure is impossible", and it must take the form `expect("why this cannot fail")`.
- **R11** Split error variants only as far as **callers handle them differently**. Each variant carries context a person can read (which tensor, which kernel). A variant that passes a driver error code up unchanged gets our own context added.

## 4. Functions, modules, duplication

- **R12** An orchestration function fits in two screens (AGENTS). A kernel body is not split (`#[target_feature]`, `#[kernel]` — a measured 10–13 % loss). The **constants and index arithmetic** of a kernel may be moved out into `const fn` helpers (they inline and the SASS is the same — if you move them, show the sameness with `ptx-scan`).
- **R13** Default visibility is `pub(crate)`. `pub` only for what another crate actually calls. A public item gets one doc sentence (what it takes and what it returns).
- **R14** **The moment a second copy appears, extract a common core** (a const generic, or an `#[inline(always)]` core plus a thin entry — kprobe's `seg_pass::<TWICE>` has that shape). A third copy is forbidden. The current `flash_latent`/`_q8`/`_seg` trio and a4c's `head_groups` with a4d's `mma_groups` violate this.
- **R15** One file, one subject. The 3901 lines of `model.rs` mix step orchestration, scratch ownership, probes and the seed cache — the axis for splitting is "who owns it" (buffer ownership = `residency`, launch order = `step`, instrumentation = `probe`).

## 5. clippy — levels and the ratchet

- **R16** Three lint levels: `deny` (only for lints with 0 hits — `unsafe_op_in_unsafe_fn`, `missing_safety_doc`), `warn` (the ones being driven down toward 0), and **`allow` with a reason** — always as `#[allow(clippy::x, reason = "…")]` per item; a crate-wide allow is forbidden. The total warning count is compared with the baseline in `AGENTS.md` Known state: **if it goes up, that round is red.**
- **R17** Close what can be closed mechanically in one round, together (`chunks_exact` constant → `as_chunks`, `is_multiple_of`, `len() < 1`, blank lines, doc indentation — 50 hits). That commit carries a **bit-identical gate plus a same-lease A/B** (R20).
- **R18** Run `cargo fmt` on the Mac, always before a commit. `just deny` (the dependency pins) is a merge gate.

## 6. Device code (cuda-oxide kernels)

- **R19** A kernel is `#![no_std]`, with no allocation and no panic. For index checks, use an **access with proven bounds** (R2) or a `get_unchecked` that carries `SAFETY`, not `debug_assert!`. Shared-memory layout (stride, padding, alignment) is `const` plus `const { assert! }` (R6), and bank conflicts are counted at compile time with cuda-device `swizzle::conflict_degree`. Declare the block shape in `#[launch_contract]` (including dynamic smem — above 48 KB, declare it as `dynamic_shared` and the launch enables it by itself), and do not duplicate it with a runtime check in the launcher.
- What the toolchain cannot do (`#[unroll]` failures, a missing intrinsic) gets one line in `docs/upstream/nvlabs-ledger.md` before any workaround (AGENTS). Say "it does not exist" only after looking in both the cuda-oxide tree and the host crates (`cuda-core`, `cuda-bindings`).

## 7. Conditions for refactoring

- **R20** A refactoring commit proves **unchanged behavior** with gates: identical tokens (`gate-gpu-e2e` 648 nodes, `gate-gpu-p8`), unchanged bands (`gate-gpu-p5`), unchanged PTX shape (`ptx-scan`: depot 0, same registers, same smem). It also proves unchanged speed with a **same-lease A/B** (±1 % ruler — bit-identical does not mean speed-identical, AGENTS). A refactoring commit missing either one is not merged.
- **R21** One round, one axis. Do not mix an unsafe comment round, a parameter struct round and a deduplication round — the diff stays readable, and if a regression appears it is attributed to one axis.
- **R22** Do not put a refactoring in the same commit as a behavior change (the code version of the incident that mixed the look core into a UI commit). If a kernel performance round wants to fix names on the way, that is a separate commit.

## 7′. Exceptions and added rules confirmed in review round 1 (2026-09-22, three agy rounds)

Only what the reviewers proposed and the lead checked against the source and accepted. What was rejected comes at the end, with the reason.

- **R1 addendum** — A contiguous vector load in a kernel (a bundle of 4 or 8 words of `get_unchecked`) needs **one SAFETY per bundle**: one line that proves the chunk bound (`base + 8 <= len`). Collective access to a shared-memory array (`SharedArray`) uses the standard phrase — `// SAFETY: block-shared, N == blockDim.x, written before the barrier that publishes it`. "as above", "as in X" and "cuda-oxide shared array access" are not SAFETY (12 places).
- **R8 addendum** — `#[kernel]` entries are **exempt** from the argument limit (the device ABI takes the arguments as they are). Host `enqueue_*` launchers are not exempt — each takes one `*Args` struct and spreads it into the kernel launch.
- **R12 addendum** — A `#[kernel]` body gets the same exemption as a `#[target_feature]` body (the measured basis is in AGENTS). The `main` of a gate binary is a linear pipeline, so it is not held to 120 lines; it is only required to be split **by logical stage (load / eager / graph / timing)**.
- **R9 exception** — `lib.rs` of `gpu-gates` (the gate helper library) keeps `Box<dyn Error>`: all its consumers are gate binaries, and a failure means exit. `GpuError = Box<dyn Error>` in `crates/gpu` is **not** an exception — it is an R9 violation and a target for a round. → Closed on 2026-09-22 by `gpuerr` (`960bde5`, 9 variants, hand-written impl). `thiserror` is a workspace dependency (`gguf`, `model`, `qdot`), so using it is not a new dependency — choosing the hand-written impl was a judgment in that round's spec and is not a rule.
- **R10 exception** — Recovering a poisoned lock (`lock().unwrap_or_else(|e| e.into_inner())`) is not an `unwrap`. A `launch().unwrap()` inside a bench loop is in a binary, so R10 does not apply.
- **R23 (new)** — **Compare and sort floats with `total_cmp`.** `partial_cmp().unwrap()` panics on NaN, and NaN is a value for the gate to catch, not a reason to panic.
- **R24 (new)** — **`let x = e.unwrap() else { … }` is dead code** (the unwrap panics first). Use `ok_or_else(..)?` or `match`. An `ok: &mut bool` accumulator argument in a check helper is the same kind — return a `bool` or a `Result`.
- **R25 (new)** — **Declare a graph handle before the buffers whose addresses it captured** (fields drop in declaration order). `Head`, `GpuModel` and `Stage` already follow this order; a new struct uses the same order plus a one-line comment.
- **R26 (new)** — **A binary whose body hides behind a feature is linted with that feature on.** `just lint` and `just check` use `--features gpu`. The runners (`depth-gpu.sh`, `ncu-gpu.sh`, `nsys-gpu.sh`) **build the binary or print the build hash in the witness** — measuring a binary that was not built is the shape of the stale binary incident (on the night of 2026-09-22 the `ik_ref` column printed an old value that way).
- **R27 (new)** — `#[doc(hidden)] pub` that exists only so an integration test can call an internal function is forbidden. Use an inline unit test, or the output that a gate observes.
- **R28 (new, 2026-09-23)** — **A function that relies on a bound the caller keeps is an `unsafe fn`.** A function whose body uses `get_unchecked` and writes "callers keep …" as its contract may stay a `pub(crate)` safe function inside the crate, but the moment it is opened outside the crate it becomes a `pub unsafe fn` with a `/// # Safety` section. The call site vouches for that bound with `unsafe { }` and a one-line `// SAFETY:`. The proof is an identical `ptx-scan` table (the move class). In the B4 wave, `q3k_sb_decode` (b4hc) and two lane bodies (b4moe) were opened as safe `pub fn` and then reverted. `cores::q3k_row_dot`, which was `pub` from the start, is the same kind.
- **R29 (new, 2026-09-23)** — **Device arithmetic whose sum order is a contract writes the contraction into the source.** cuda-oxide fuses `a*b + c` into one FMA, like nvcc's `--fmad=true` (`docs/upstream/nvlabs-ledger.md` line 17). So a host rule that writes the same expression as `*` and `+` and a kernel round differently — in b4hc's first run, 319 of 320 places differed in bits. Write `mul_add` or `fma` where the ops should fuse, and `mul_rn_f32` or `add_rn_f32` where they should round separately. The proof is the `fma` column of `ptx-scan`. For a core whose doc says "plain multiplies" or "no fused multiply-add" but whose PTX is FMA, fix the doc to match the PTX (the `weighted_sum` and `moe_combine` bodies in `elem.rs` — b4moe report).

**Rejected**: ① Extracting a common core from the `flash_row_scalar`/`flash_row_avx2` twins (the cpu review's priority 1) — this collides head-on with the ban on splitting a `#[target_feature]` body (AGENTS, measured 10–13 %). The twin is the intended shape, and the `TWIN` comment is the contract. What remains is to move the softmax scan arithmetic **outside** the twins into an `#[inline(always)]` core, showing identical SASS and A/B — a separate round, not now. ② The `head.rs` drop order defect — the graph already comes first (a false positive; accepted only as rule R25). ③ The reviewer's claim that "cuda-oxide cannot take struct arguments" is unconfirmed, so it was not used as a basis for the R8 addendum (the ABI reason is enough).

## 8. Review procedure

1. A reviewer (an investigation round) reads one crate at a time and reports violations as `path:line — R-number — one line — size (XS/S/M/L)`. The reviewer does not assign severity — the rule number is the classification. The reviewer does not fix code.
2. The lead disposes of each item as one of three: this round / tracker / rejected with a reason (that reason rises into a rule exception in this document or becomes an `allow(reason)`).
3. A refactoring round (implementation) takes one axis (R21), a file whitelist, and the gates and A/B of R20 as its completion conditions.
4. When a round ends, re-measure the §0 table and update this document. If the table moves in the rising direction, that round is the cause.
