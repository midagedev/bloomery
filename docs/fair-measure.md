# 공정 측정 계약 — 교차 엔진 공개 행

사용자 지시(2026-09-28): "웜업도 그렇지만 가급적 그 외에도 최대한 공정하게 측정해야해 재측정시에". 공개 표에 서는
교차 엔진 행(README, rig-log 헤드라인, 공개 글)은 아래 조건을 모두 만족해야 한다. 조건마다 **누가 지키는가**를
적었다. 러너가 검사하는 조건은 어기면 행이 FAIL이 되고, 카드가 적는 조건은 `tools/ref/card.py check`가 카드에 그
줄이 있는지 본다. 사람의 확인에 맡기는 조건은 가능한 한 없게 둔다(AGENTS: 머신 규약은 지시문이 아니라 러너로).

이 계약은 조용한 기계 규약(`tools/ref/lease.sh`, rig-log `docs/quiet-machine.md`)과 「Derive first」 위에 얹힌다.
그 둘이 이미 지키는 것은 여기서 다시 적지 않는다.

## 1. 같은 입력

| # | 조건 | 지키는 곳 |
|---|---|---|
| 1.1 | 두 엔진이 **같은 토큰 id 열**을 먹는다. llama.cpp는 `llama-bench`(반복마다 무작위 id)가 아니라 `llama-server`에 id 배열로 넣는다. | 러너(`tools/ref/lcpp-warm.sh`): 서버가 돌려준 프롬프트 토큰 수가 우리 id 수와 다르면 FAIL |
| 1.2 | 디코드는 같은 깊이 D, 같은 생성 길이 n = 96, greedy, 같은 정지 조건(EOS 무시)이다. | 러너: 생성 토큰 수가 n이 아니면 FAIL |
| 1.3 | 프롬프트 캐시는 끈다(`cache_prompt=false`). pp는 매번 전체 P를 계산한다. | 러너 |
| 1.4 | 같은 모델 파일이다(첫 샤드 전체 경로와 크기). 다른 양자화(exl3 등)는 따로 표를 만들고 비율을 내지 않는다. | 러너 증인 줄, 카드 |
| 1.5 | 할당 문맥이 같다. llama.cpp `-c`는 우리 `--ctx`와 같은 값으로 둔다. | 러너 |

## 2. 같은 상태 — 웜업

| # | 조건 | 지키는 곳 |
|---|---|---|
| 2.1 | 모든 팔은 **같은 id로 웜업 요청을 한 번** 보내 버린 뒤에 시간을 잰다. 우리 팔도 같다. | 러너 |
| 2.2 | 엔진 블록마다 그 엔진의 호스트 집합을 페이지 캐시에 예열한다. 두 엔진의 집합이 램에 함께 들지 않으면 블록 순서로 가르고, 블록 첫 실행은 버린다. | 러너(`BLOOMERY_AB_ORDER=blocks`, 예열) |
| 2.3 | 웜업 뒤에도 `[cold]`(창 안 폴트 × 75 µs ≥ 창의 1 %)인 행은 한 번 다시 잰다. 그래도 차가우면 FAIL-cold 행이 되고, 공개하지 않는다. | 러너(`cold-blocks.sh` 재시도 스위치) |
| 2.4 | `[cpu-busy]`와 `[other-busy]` 행은 공개하지 않는다. 러너가 자기 팔을 세지 않아야 한다(`pplbrec`이 고친다). | 러너 |

## 3. 참조 엔진도 가장 빠른 설정으로

| # | 조건 | 지키는 곳 |
|---|---|---|
| 3.1 | llama.cpp의 배치는 수작업(`--n-cpu-moe K`)과 자동(`-fitt`)을 둘 다 재고, 더 빠른 쪽을 싣는다. 수작업 K는 카드에 들어가는 가장 작은 값이고, 그 값을 찾은 근거(적재 로그의 버퍼 크기)를 카드에 적는다. | 카드, 러너(fit 쌍둥이 팔) |
| 3.2 | 프리필은 기본 ub와 `-ub/-b 4096`(카드에 들어갈 때)을 둘 다 재고, 빠른 쪽을 싣는다. 들어가지 않으면 FAIL 행으로 남기고 이유를 적는다. | 러너, 카드 |
| 3.3 | 스레드 수는 우리와 같은 코어 집합에서 `-t`를 두 값 이상 재고(예: 16, 32) 빠른 쪽을 싣는다. | 카드(팔 목록) |
| 3.4 | 우리가 호스트 집합을 `mlock`하거나 미리 읽는 팔이면, llama.cpp에도 `--mlock` 팔 또는 같은 예열을 준다. | 카드 |
| 3.5 | 참조 빌드는 재측정 시점의 헤드(메인라인, 또는 그 모델의 PR 헤드)로 다시 빌드하고 커밋을 적는다. 빌드 플래그는 메인라인 트리의 `CMakeCache.txt`와 같다. | 러너 증인 줄(`head=`, `dirty_files=`) |

## 4. 같은 기능끼리 비교

| # | 조건 | 지키는 곳 |
|---|---|---|
| 4.1 | 평문 디코드는 평문과, 투기 디코드(MTP, DSpark)는 투기와 비교한다. 한 표에 섞으면 열 이름에 적는다. | 카드 |
| 4.2 | hot list는 **측정 프롬프트와 겹치지 않는 텍스트**에서 만든다(held-out). 지금 V4.1과 GLM의 hot list는 같은 코퍼스의 추적에서 나왔으므로, 재측정에서는 추적에 쓰지 않은 구간을 프롬프트로 쓴다. 그럴 수 없으면 행에 "유리한 경우"라고 적는다. | 카드(프롬프트 id 범위, 추적 id 범위) |
| 4.3 | 두 카드 표는 참조 엔진에도 같은 두 카드를 준다(`-ts`, AGENTS 예외 2026-09-28). A6000 한 장 표와 섞지 않는다. | 러너(`twocard`) |

## 5. 같은 자

| # | 조건 | 지키는 곳 |
|---|---|---|
| 5.1 | tok/s의 정의가 같다. 디코드는 첫 토큰 뒤 n개 생성의 벽시계, pp는 P개 프롬프트 계산의 벽시계이고, 적재·토크나이즈·HTTP 왕복은 뺀다. 서버 `timings`와 우리 기록이 같은 구간을 재는지 러너 주석에 적는다. | 러너 |
| 5.2 | 두 엔진의 팔을 한 임대 안에서 바퀴마다 순서를 돌려 번갈아 잰다. 비율은 같은 바퀴 짝의 비의 평균과 t 95 % 구간으로 낸다. 그 구간이 1을 포함하면 "같다"라고 쓴다. | 러너(`ratio_table`) |
| 5.3 | 바퀴 수는 주장하려는 차이에 맞춘다(`tools/ref/card.py`가 자로 계산). | 카드 |

## 6. 같은 답

| # | 조건 | 지키는 곳 |
|---|---|---|
| 6.1 | 빠르지만 틀린 행은 싣지 않는다. 시간을 잰 뒤 두 엔진의 greedy 첫 토큰 몇 개를 대조하고, 갈리면 행에 이유를 적는다(양자화·반올림 차이인지, 다른 모델을 도는지). V4.1 PR #28696이 다른 모델을 돈 적이 있다. | 러너(첫 토큰 대조 줄) |

## 7. 공개 규칙

- 한 행에 조건이 하나라도 빠지면 그 행은 공개 표에 서지 않는다. 자리에는 이유를 적는다.
- 가장 유리한 바퀴를 골라 싣지 않는다. 비율은 같은 바퀴 짝의 평균이다(2026-09-28 V4.1 릴리스 표의 "llama.cpp에 가장 관대한 행"은 이 계약 이전의 임시 규칙이었고 재측정으로 대체한다).
- 지는 행도 싣는다(Qwen3.8).
