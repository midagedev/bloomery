## 자원 시간선

**디코드 (토큰당)**

- 산문, 깊이 512, A6000: plain 44.8 tok/s (`README.md:66`, rig-log 09-25 #dspark-loop-tps의 p50 22.17–22.86 ms). 토큰당 22.3 ms [derived].
- nsys 행은 조건이 다릅니다(깊이 6, n = 8, A6000; `plan-triage.md:120`). 그래서 위 값과 한 표에 두지 않습니다.
  - 스텝 31.6 ms = 카드 임계 8.56 + 브리지 24.06
  - 브리지 = 36.0 + 119.5·k_host µs
- 층마다 카드(attention, route) → 호스트(고정 풀의 expert 서비스, DRAM) → 카드(join)로 이어지는 사슬입니다. 층 안에서는 카드 쪽 shadow가 호스트 구간 아래로 겹치므로 max입니다. 벽은 브리지가 정합니다.
- NVMe는 정상 상태에서 0입니다. 호스트 세트는 적재 때 populate됩니다 (AGENTS `BLOOMERY_HOST_POPULATE`).
- 결론: 오케스트레이션을 합쳐도 m = 1의 캡처 노드 목록이 같으면 두 항 모두 움직이지 않습니다. 디코드 비용은 0입니다.

**프롬프트 (층-배치당, G 뒤)**

- lcg, 목록 없음, P 4096: 호스트 union이 73.8 ms 중 68.6 ms로 병목입니다 (`plan.md:110`).
  - 카드 route 21.9 + shadow 11.7 = 33.6 ms (#prefillgroup-ab)는 그늘 아래라 값이 0입니다.
- 산문, 목록 384: 카드가 병목입니다. 모형 49.5 ms, 카드 duty 0.87 (`plan.md:110`).
  - T 착륙 시점의 P 4096에서 카드 22.5+21.7 = 44.2 ms, 호스트 39.1+4.7 = 43.8 ms로 거의 맞섭니다 (#cardtile-ab).
- PCIe (P 512)는 카드 FIFO 안에 있고, 합 ≈ 1.1 ms [derived]입니다.
  - D2H 547.6 µs (x 10.49 MB, ids, weights)
  - H2D 551.9 µs
  - 출처 `constants.tsv:103-104`
- 청크별 카드 작업 ≈ 6.9 ms/층-배치는 산문에서만 임계 경로에 있습니다.

**흐름 레버**

- **SIMT**: 토큰별·청크별 카드 커널을 배치 폭으로 바꿉니다(DS2).
- **bulk**: embed와 engram 행이 토큰마다 launch 하나입니다 (`body/prefill.rs:748-760`).
  - `t_issue` 2.42 µs (`constants.tsv:60`)로 치면 embed만 배치당 ≈ 1.24 ms [derived]입니다.
  - 값은 작지만 큐(Q ≈ 1,080–1,170)를 채웁니다.
- **비동기**: 이미 했습니다(G, pair). DS6은 이 둘이 같은 모양이라는 점을 다룹니다.
- **라운드를 열지 않는 것**: `ds41_card_buckets`는 블록 하나로 돕니다 (`chain/ffn/batch.rs:960`). 129.2 µs/층-배치 (`constants.tsv:110`)로 `card_in` 23.1의 ≈ 0.56 % [derived]이고, 자 아래입니다.

## 4. 교차 패턴

- **상한이 API로 샙니다.** 커널의 타일 폭이 타입 생성자, 체인 입력, 스케줄러 상수가 되었고, 모든 소비자가 토큰 수별 벡터를 듭니다. crates/gpu의 다른 m열 소비자(Qwen3, V2-Lite)도 같을 수 있습니다 [가설].
- **라운드마다 앞 경로를 팔로 남기고, 판정 뒤에도 지우는 날짜가 없습니다.** 팔은 코드, 게이트 항목, 모형 변형으로 계속 비용을 냅니다.
- **Rust 구조를 Python이 옮겨 적고, 줄 인용이 어긋납니다.** q3pp 계열도 같은지 볼 만합니다.
- **할당 식이 할당자 옆에 사본으로 있습니다.** `chain/ffn.rs:1483` `hc_pre_scratch_bytes`, `:1490` `q8act_bytes`. 타입의 `device_bytes()` 하나면 됩니다.
- **모델 상수를 커널 본문의 컴파일 시간 크기로 박아서 커널 사본이 생깁니다.** `dflash_router`는 `ds41_router`의 본문입니다 (`experts_mxfp4.rs:5-12`, `router.rs:137`).
- **게이트 API가 엔진 타입에 삽니다** (`Body`의 약 20개). 다른 모델의 body도 비슷할 수 있습니다 [가설].

## 5. 옛것처럼 보이지만 남는 것

- **`BLOOMERY_CED=off`와 `Need::all`**: 걷기 전제를 깨는 파일에서 쓰이고, 흐름 모형의 CED-off 교정 실행도 아직 열려 있습니다.
- **`PREFILL_GROUP=1` 경로**: P ≤ 512는 늘 1개 그룹입니다 (`prefill.rs:377-389`). 착륙 배치의 `@…=1` 항목(363 s)이 하는 일은 기본 게이트가 다배치 그룹 순서로 이미 덮는다고 봅니다 [가설]. lead가 사례 목록을 보고 판단할 몫입니다.
- **`PrefillMode::Steps`**: 둘째 구현이 아니라 디코드 스텝 그 자체이고, prefill 게이트의 기준입니다.
- **`Seam`**: 구현은 하나이고, `enqueue_chain`은 no-op observer로 부릅니다 (`body.rs:1953-1955`). llama.cpp `cb_eval`과 같은 모양입니다. DS6에서 합쳐지는 것은 `BatchSeam`뿐입니다.
- **`take_host_refusal`**: 엔진 오류의 이름 붙이기입니다 (`body.rs:2044` → `crates/gpu/src/model.rs:879`).
- **`BLOOMERY_ENGRAM_HELPER`**: 차가운 행에서 11–15배 빠릅니다 (AGENTS).
- **load3 `RowsArrival`**: +0.07 % ± 0.63 %로 예측은 기각됐지만, 차가운 첫 요청의 구조를 바로잡는 코드라 남기기로 결정했습니다.
- **호스트 rope 표**: ik와 비트가 정확합니다 (`rope.rs:19-24`).
- **`Rule::Ik`**: 데이터입니다 (`draft/block.rs:75-89`).
- **초안 폭별 그래프, `join_projections`, 링 섀도**: 제품입니다 (README DSpark 51.3).
- **`step_pair`/`decode_pair`**: DSpark 검증 패스, 곧 제품입니다. DS6에서 m = 2 스케줄로 흡수됩니다.
- **`BLOOMERY_STEP_PAIR=1`**: 타이밍 팔입니다. 생성 텍스트가 반복으로 무너집니다 (AGENTS). `generate_ds41`에 있으며 범위 밖입니다.
- **vision 두 크레이트**: 멈춘 M5이고, 주입 경로(`visinj`)는 짓지 않았습니다. 살아 있는 사용처는 `gate_vision_encoder`뿐입니다.
  - 비용은 `just gate`의 gate-vision (`justfile:744`)과 check/lint의 feature (:20, :28)입니다.
  - 주입 일정 전까지 `just gate`에서 뺄지는 lead가 판단합니다. 빼면 커버리지 변화이므로 날짜와 이유가 필요합니다.

## 6. 오늘 다시 짓는다면

**모듈 구성**
- `seq/`: `SeqState` (위치의 소유자, holds, holes, CED need, `keep_point`/`rollback`, 호스트 테스트)와 `KvCache` (링, 섀도, restore 하나).
- `ops/`: 지금의 연산 모듈들. 각 연산은 `enqueue(m, …)`이고, 커널 선택(1열 fused / m열 / T 폭)은 연산 안에 둡니다. 8은 여기서만 보입니다.
- `layer.rs`: 층 프로그램 하나. 호스트 구간 앞뒤 두 반쪽으로 나뉩니다.
- `exchange/`: Free → Routed → Served 프로토콜 하나(키 (layer, unit))와 transport 둘.
- `sched/`: `decode` (m = 1 캡처), `verify` (m ≤ 8 캡처), `prompt` (m ≤ 512, CED, G). 겹침 파이프라인은 공유합니다.
- `stage.rs`: pinned 아레나 하나.
- `inspect.rs`: 게이트 API (feature).
- `draft/`: `ops`를 씁니다.

**소유자**
- 위치 = `SeqState`
- launch 수 = 세는 스트림 래퍼
- 흐름 모형 = `--plan` 덤프를 읽는 쪽
- `top_k` = 층 설정

**이행 순서** (각 단계에서 게이트는 녹색, 괄호는 증명 클래스)
1. 삭제: DS1, `step_plan`/`engram_layers`, overlap 팔 [03]. (기본 팔 비트 불변, `ptx-shapes.tsv` 엔트리 제거에 날짜와 이유)
2. `SeqState`/`KvCache` 추출, restore 한 곳으로. (이동: ptx-scan 동일, 스텝 구조 검사, dsloop 핀, eager = replay)
3. launch 계층에서 세기, `--plan` 덤프, `queue` 제거. (호스트 계측: 같은 실행의 `stat` 줄 불변)
4. engram 실험실 분리, `token_map` 적재 검사. (유효 입력 비트 불변)
5. `Q8Act` view, 토큰별 연산을 T 폭으로. (launch 수 + 기하: prefill 게이트, 산문 A/B 1회. 카드는 `shadow_chunk` 항에서)
6. 층 프로그램 하나로 통합. 두 스케줄이 오늘과 같은 launch를 냅니다. (이동: 디코드 노드 동일, 프롬프트 launch 목록 동일은 3단계 덤프로)
7. `verify` 스케줄로 pair를 대체하고 uniongroup을 매개변수로 만듭니다. (새 스케줄만 바뀜, A/B는 트리아지 :21 카드)
8. V4-Flash 변형을 `ops`와 `layer.rs`에 한 번만 씁니다. (새 모델 게이트)
