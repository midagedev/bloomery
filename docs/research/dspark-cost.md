# DSpark 드래프트의 값 — 이 엔진에서 먼저 유도한 것 (2026-09-24 새벽)

사용자 요구: "ik는 DSpark까지 써서 27 tok/s 근처를 냈다. 우리도 관련 구현까지 다 해 보자. 그리고 ik보다
더 혁신적으로." 이 메모는 구현 전에 값을 유도한 것이다(AGENTS.md "Derive first"). 숫자는 전부
[유도]이고 입력은 아래 표의 실측뿐이다. 결론은 둘이다 — **ik 방식 그대로는 우리 엔진에서 손해**이고,
**한 층 어긋난 파이프라인**이 이기는 길이다. 구현 여부는 사용자 판단.

## 같은 규칙에 우리 항을 넣으면

드래프트 비용 D는 미측정 — 3090(유휴)에서 3 ms와 10 ms(ik 값) 두 팔.

| 팔 | 패스 ms | 토큰/패스 | tok/s (D=3) | tok/s (D=10) |
|---|---|---|---|---|
| 드래프트 없음(지금) | 39.49 | 1 | **25.3** (실측 25.4) | — |
| ik식 배치 k=1 | D + 12.95 + 2×26.54 = 66.0+D | 1.702 | 24.7 | 22.4 |
| ik식 배치 k=2 | D + 12.95 + 3×26.54 = 92.6+D | 2.140 | 22.4 | 20.9 |
| ik식 배치 k=3 | D + 12.95 + 4×26.54 = 119.1+D | 2.434 | 19.9 | 18.9 |

**ik 방식은 우리에게 손익분기 아래다.** 이유는 한 줄이다: 검증이 상각하는 것은 dense 몫뿐이고, ik는 그 몫이
65 %(32.9/50.2)인데 우리는 33 %(12.95/39.5)다. k=1 손익분기 dense 몫 f는 `1.702 = D/base + f + 2(1−f)`에서
`f = 0.298 + D/base` — D=3이면 0.374, 우리는 0.328. 라우팅 expert 바이트는 토큰마다 다시 읽히므로(두 토큰이
같은 expert를 고를 기대값 층당 0.09) 어떤 검증도 **수락 토큰당 호스트 바이트를 한 토큰치 아래로 못
내린다**. 트리 검증(SpecInfer·Medusa류)은 위치 수를 늘리므로 여기서는 더 나쁘다.

B12(뜨거운 expert 집합, 호스트 3.409 → 2.15–2.51 GB, 다리 26.54 → 14.6–17.0 ms; 15.8로 놓음) 뒤에도 ik식
k=1은 `1.702/(12.95+31.6+3)` = 35.8 tok/s 대 드래프트 없음 34.8 — +3 %다.

## 어긋난 파이프라인 — dense를 상각하지 않고 숨긴다

검증 배치의 두 행(수락된 토큰 t, 드래프트 t+1)을 층마다 함께 돌리지 않고 **행 t+1이 한 층 뒤따르게** 한다:
카드가 t+1의 l층 attention·라우터를 도는 동안 호스트가 t의 l층 expert를 읽는다. 의존은 성립한다 — t+1의
l층 attention은 t의 l층 KV(t의 attention이 쓰고, t의 expert보다 먼저)와 자기 l−1층 출력만 필요하다. 그러면
패스 ≈ 층마다 max(호스트 2행, GPU dense 2행)의 합 + D ≈ `2×26.54 + D`.

| 팔 | 패스 ms | tok/s (D=3) | 드래프트 없음 대비 |
|---|---|---|---|
| 어긋난 k=1, 지금 | 53.1 + D | **30.3** | +20 % |
| 어긋난 k=1, B12 뒤 | ~~31.6 + D~~ max(2m, 2(G+ce)) + D — B12 뒤에는 카드가 공동 임계다(specresearch 정정: 2m 33.6–39.2 대 2(G+ce) 32.5) | ~~**49.2**~~ **40.0–46.1** | +30…+37 % |
| 어긋난 k=2, B12 뒤 | 47.4 + D | 42.5 | k=1이 낫다 |

숨는 것은 GPU dense 12.95 ms 중 호스트 다리 그늘에 들어가는 몫이라 상한이 −12.95 ms/패스다. 첫 층의 t
attention과 마지막 층의 t+1 expert·헤드는 안 숨는다(~1 ms, 위 표에 안 넣음). 같은 산술이 **독립 스트림 둘**
(서버 C3)에도 그대로 선다 — 수락률 1.0이라 `2/(53.1)` = 37.7 tok/s 합계.

**specresearch(09-24 04:05, 원문 [`spec-decoding-report.md`](spec-decoding-report.md), 출처 12개 대조)가 더한 것.** ① 검증 행에 층 어긋남을 거는 선행 사례는 확인한 문헌에 없다 — 가장 가까운 KTransformers의 Expert Deferral은 한 행 안에서 CPU expert(l층)와 GPU attention(l+1층)을 겹치되 모델을 바꾼다(expert 출력을 l+2층으로 미룸). 우리 어긋남은 둘째 행으로 같은 겹침을 무손실로 얻는다. ② D는 어긋남 뒤 몫이 작다: D 3→0이 30.2→31.9인데 수락률 0.70→0.85가 34.6이다. 그래서 **앞서 달릴 수 있는 싼 드래프트**가 둘째 후보다(09-24 05:50 E5·E6 답: n-gram lookup은 code 0.595·threads 0.477로 통과, korean 0.29 불통과; Markov 헤드 단독은 0.06–0.08로 **닫힘**) — DSpark의 Markov 헤드 단독(66 MB, D≈0.15 ms, 직전 토큰만 입력이라 검증과 겹쳐 달린다; 손익분기 수락률 0.36, 오프라인 argmax 일치율로 몇 분에 잰다)과 n-gram. DSpark 본체는 37–39층 은닉을 읽으므로 앞서 못 달린다. ③ k는 1로 고정 — 어긋남에서도 k=2는 25.8로 손해. ④ 상주 expert 자기 드래프트는 손익분기 a>0.71인데 DraftExpert의 사전 근거가 50 % 아래라 낮은 순위. ⑤ 트리 검증·prefetch 계열은 이 물리에서 이득 없음. ⑥ 상한: 검증이 위치마다 m을 읽는 한 a=1이어도 1000/m = 37.7 tok/s(오늘). 서빙이면 어긋난 2스트림이 투기 없이 같은 자리(합계 37.5)를 준다.
